# Main-scenario progress and full code review — 1.1.0.0

Reviewed 2026-10-25. Scope: all production C# files, configuration migration/recovery, runtime acquisition, worker shutdown, Lodestone HTTP/image handling, CSV output, localization and UI state. This is a code, synthetic-test and offline-game-data review; it cannot establish that no bugs remain.

## Main-scenario progress

Overview has a horizontally scrollable Main Scenario column; character details include a separate Main Scenario tab. Captured fields are quest ID/name, journal chapter, state, internal quest sequence and changed-observation time. Names come from the installed client's data language. Sequence is not a percentage.

The reader uses runtime `QuestManager` and `AgentScenarioTree` APIs only. It never calls quest actions or sends additional requests. After a short login settling period, checks occur at most once per 10 seconds, plus explicit/ordinary character refresh. The metadata catalogue is loaded once and cached. Unchanged observations do not update timestamps or mark configuration dirty. Offline records retain their last observation; unavailable reads preserve existing data. Three exceptional acquisition failures stop this reader with one notification; Refresh Current Character resumes it.

Accepted, not accepted and last-completed guide states are distinct. A unique endpoint is calculated from the installed main-scenario prerequisite graph; only a confirmed completion of that endpoint yields Latest available story completed. Empty guides and ambiguous metadata do not prove completion. New Game+ guide entries cannot downgrade a confirmed complete endpoint.

## Reproduced/reviewed issue groups and fixes

| Area | Previous behavior / reproduction | Result |
| --- | --- | --- |
| Lodestone identity | A partial-name hit before the exact match supplied the wrong first ID; profiles were not rechecked | Exact name/world required in both card and profile; ambiguous matches return no result |
| Face/HTTP failures | Image failure discarded an already found ID; generic OG logos could be marked as faces; automatic redirects escaped host checks; bodies had no HTML limit | ID retained independently, only face markup accepted, bounded body/deadline and official HTTPS redirects, image signature checks, one-second spacing for every HTTP request |
| Concurrent manual edit | A queued lookup overwrote a manually edited ID and left mismatched face data | Compare expected ID before applying completion; ID changes invalidate the old face |
| Login readiness / early playtime | Slow player loading consumed the three-failure budget; a response before successful full character capture was silently dropped | Normal loading waits at one-second intervals without logging/saving or consuming failures; the plugin buffers early playtime by Content ID until successful capture, clearing it on logout |
| Configuration recovery | Future configuration version was treated as corrupt and replaced from an older backup; malformed character fields could later break UI/lookup | Future versions block writes without downgrade; semantic invalid records are rejected for normal recovery |
| Backup maintenance | Failed cleanup was never retried once the snapshot was clean | Checkpoint retries cleanup separately, stops at three and supports explicit recovery without duplicate commits |
| Rendering / UI identity | Every frame deep-cloned all records and checked face-file existence; 64-bit IDs were truncated for row controls; wide tables hid columns | Revision-cached UI snapshots, cached texture-provider access with failed-path suppression, full Content IDs, stable tab IDs, horizontal scrolling and wrapped details |
| CSV durability | Destination was directly truncated; automatic names could collide in one second; dialog could export an old snapshot | Validate/write temporary payload then replace, unique automatic names, current snapshot when the save dialog completes |
| Localization / privacy | Non-Japanese missing keys displayed bracketed text; dynamic acquired-ID text bypassed translations; routine logs included character identity | English fallback, keyed formatting and all-UI resource checks; routine diagnostics omit names, Content IDs and playtime values |

API/game-data references are documented in both READMEs and THIRD_PARTY_NOTICES.md. No upstream plugin code/scripts/assets or game data files are redistributed. Shared UI templates were not changed.
