# Housing-transition crash investigation — 1.2.0.1

## Evidence and certainty

The user-supplied 2026-11-17 17:49:18 crash record reports an unhandled CLR exception. The managed/native stack is `IL_STUB_PInvoke -> CharacterArchive.Plugin.OnUiModulePacket -> IL_STUB_ReversePInvoke -> PacketDispatcher.HandleUIModulePacketPacket`. The preceding AutoRetainer log shows house confirmation at 17:49:16 followed by waiting to leave the zone. AutoRetainer's action explains the trigger but does not prove that plugin caused the exception.

In affected code, the original UI handler delegate was called before the type filter and outside the try/catch. Thus every UI packet, including housing transitions, crossed the plugin's reverse-P/Invoke boundary, and failures at the forwarding boundary could escape to native code. The crash stack places the failure at/under that call, before playtime-specific processing; it does not establish the exact exception subtype, underlying original target failure, or whether another hooked caller contributed. The earlier optional-initialization fix did not protect runtime forwarding.

The log/dump and unrelated personal logs were only read locally. No raw log content, character data, memory addresses or dump files are redistributed.

## Fix

- Remove the plugin-owned UIModule virtual-table hook, original delegate, OnUiModulePacket callback, raw packet read and IGameInteropProvider dependency entirely. Ordinary game packet handling no longer enters a Character Archive native detour.
- Observe the supported IChatGui.LogMessage event instead. Only standard playtime message 859 is eligible; copy three integer day/hour/minute parameters while ILogMessage remains valid, together with the current Content ID. Do not format/debug, retain, suppress or modify the host message.
- Queue only primitive-value observations for normal framework processing. The callback performs no configuration IO and does not execute commands. Existing standard /playtime requests, login readiness and ten-second command limit are retained. No custom/server packet path is introduced.
- Bound exceptions from getters, conversion, character access and delivery. Stop after three consecutive targeted failures and report once. Even reporting failures cannot escape. Unrelated log events inspect only the message ID, with no parameter/character access, allocation or save.
- Dispose the receiver and unsubscribe the managed event during unload. Late callbacks are ignored, and queued data is independent of the expired host message. Failed partial subscription is detached; optional feature failure leaves other features available.
- Require Dalamud 15.0.4.0, the runtime documented in the user's crash, to ensure the structured LogMessage API is available. Do not force a deprecated hook backend or alter any other plugin's hooks.

## Executed checks

- Built against the exact installed Dalamud 15.0.4.0 libraries: zero warnings/errors.
- 28 new checks: no native callback/hook references in source; subscription pairing; normal/zero/max playtime; invalid ranges/overflow; 10,000 unrelated logs; expired message lifetime; logged-out data; failing ID/count/parameter getters; malformed parameter shape/type; character/delivery/reporting exceptions; three-failure stop and one report; valid-response recovery; detach once; partial subscription rollback.
- Existing nine optional-resource, 18 expansion, 43 persistence, 57 review and core/seven-language checks passed.
- 112 offline game-data checks passed, including four added checks that message 859 uses the same three numeric day/hour/minute parameters in Japanese/English/German/French. No localized chat-text matching is required. No live character data or game command was used.
- Runtime DLL metadata was read with Mono.Cecil: no OnUiModulePacket method and no HookFrom*, IGameInteropProvider, Marshal.ReadInt32, HandlePacket or UIModulePacketType references remain. The outbound standard text-command service remains separate.

## Remaining verification

The live housing transition has not been reproduced in a running game after the change. This fix removes the implicated plugin-native entry path; it is not proof that all possible housing/network crashes or other plugins' interactions are resolved. Update and fully restart FFXIV before retesting the same AutoRetainer house entry, so the previous process's hooks are absent. Do not delete saved configuration. No installed DLL, settings, running process or other plugin was modified during this investigation.
